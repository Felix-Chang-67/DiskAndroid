# 测试节点 N3b：DVD 正片没声音、一顿一顿；蓝光为什么打不开

- 版本：`0.10.1-N3b`（versionCode 13），直接覆盖安装。
- 解密组件没有变，**不用重新导入**。

## 上次（N3）的结果
- **加密 DVD（CSS）**：你的光驱认证成功了，商业 DVD 能播放。
- 但有两个问题，都是播放器的 bug，这版已修：
  1. **正片没有声音**，直到你手动换了一次音轨。
     - 那张盘的正片只有一条 LPCM 音轨，光盘程序也没有指定用哪条。
     - 播放器按 AC-3 格式去找音频，结果一个包都没收到。
  2. **画面一顿一顿的**。
     - 日志里每 10 秒正好显示 240 帧，没有丢帧，但每隔一会儿就有一次约 140 ms 的停顿。
     - 原因：DVD 上的电影是 24 帧，用"软 3:2 下拉"存放（每隔一帧多显示一场）。一个 GOP（约半秒）里只有第一帧带时间戳。
     - 其余帧的时间是推算的，以前按每帧 1/29.97 秒算，漏算了多出来的那一场。结果半秒内播快了约 100 ms，然后停住等下一个时间戳。
     - 在电脑上用模拟数据重现，最长间隔 133 ms，和你日志里的 139–143 ms 对得上。
- **蓝光**：两张都打不开。原因见下，不是 App 的 bug。

## 这次改了什么
### DVD
- **音轨格式**：按光盘实际选中的音轨查格式。光盘没指定时，按 libdvdnav 实际播放的那条查。
  - 万一 IFO 里写的格式和盘上的流对不上：选中的格式连续几秒没有数据、另一种格式一直有时，自动改用它。
  - 正片放完回菜单时，不再截掉最后一点声音。
- **画面节奏**：
  - 每一帧按它实际的显示时长（2 场或 3 场）接到时间轴上。
  - 24 帧的电影均匀地每 41.7 ms 显示一帧。以前是每帧约 33 ms，然后停 133 ms。
- **屏幕刷新率**：
  - 告诉系统的帧率跟着内容变：菜单 59.94，电影 23.976。
  - 播放界面会请求刷新率是帧率整数倍的屏幕模式（电影 → 120 Hz，每帧正好 5 次刷新）。
  - 日志里会记下"视频帧率 … 请求屏幕 …"和"屏幕刷新率 …"，能看出系统有没有照办。

### 蓝光
- 打开失败时说清楚原因。
- "视频内容"里事先显示：盘 ID、MKB 版本、总线加密、KEYDB.cfg 里有没有这张盘，以及大概能不能播。要在 KEYDB 里查一下，会晚一两秒出来。

## 蓝光为什么打不开（看了日志）
1. 你导入的 KEYDB.cfg（66 MB）里**没有这两张盘**。
2. 库里的处理密钥算出了这两张盘的"媒体密钥"（MKB 版本 61 和 72）。
3. 还差一个"卷标识"，要向光驱读，读之前要用主机证书和光驱认证。
   - 库里只有一个公开的主机证书，**光驱拒绝了它**：返回 5/6F/00（认证失败）。
   - 这个证书已经被新盘带的吊销列表吊销了。
4. 更关键：这两张盘都**开了总线加密**，你的光驱也支持总线加密。
   - 这种组合下，光驱送出来的视频数据还有一层加密，那一层的密钥只能通过和光驱认证拿到。
   - 所以**就算以后 KEYDB 收录了这两张盘，在这台光驱上也播不了**。

结论：用公开的密钥库（libaacs）这条路，在这台光驱上只能播**没开总线加密、并且 KEYDB 里有这张盘**的蓝光（多半是较早的盘）。我不能提供没有公开的证书或密钥。

## 测试步骤
1. 覆盖安装。
2. 上次那张商业 DVD，从光盘菜单进正片：
   - 正片一开始就应该有声音，不用手动换音轨。
   - 看画面是不是流畅了。放 2–3 分钟。
3. 上次那张 DVD+RW（如果还在）：放 1–2 分钟，看是否流畅。
4. 两张蓝光放进去，看"视频内容"里的预判文字。如果有别的蓝光（尤其是较早出的盘），也放进去看看预判和能不能播。
5. 测完点"导出日志（zip）"发给我。
