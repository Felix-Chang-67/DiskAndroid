# 测试节点 N0 + N1.1：安装、USB 枚举与权限

- 版本：`0.1.0-N1.1`（versionCode 1），release 构建，约 2.4 MB，测试签名
- 这个版本**只做 USB 层面的只读检查**：不发送任何 SCSI 命令，不会读写光盘，可以不放光盘测试。

## 1. 安装

1. 在对话里下载 APK 附件。
2. 打开 APK 安装。如果系统提示"禁止安装未知应用"，按提示给打开它的应用（Claude App / 浏览器 / 文件管理器）开启"允许安装未知应用"。
3. HyperOS 可能弹出安全检查或"纯净模式"拦截：选择继续安装，或者暂时关闭纯净模式。
4. 以后的版本直接覆盖安装即可（签名固定），不需要先卸载。

## 2. 测试步骤

### A. 不接光驱启动
1. 打开 DiskAndroid。应看到"测试节点 N1.1"说明卡片和"未检测到 USB 设备"。
2. 横屏时左边是设备、右边是日志；竖屏时是"设备 / 日志"两个标签页。

### B. 接上光驱（可以不放光盘）
1. 扩展坞接好电源，插到平板；光驱的两个 USB 头都插到扩展坞上。
2. 系统询问"要打开 DiskAndroid 来处理……吗"时点"确定"（可以勾选默认使用）。
3. App 会自动做一次"连接测试"。设备卡片应显示"连接测试成功"，以及链路速度、声明最大电流、Max LUN。
4. 如果卡片显示"尚未获得 USB 权限"，点"申请权限"，在系统弹窗里允许。

### C. 拒绝一次权限
1. 拔掉光驱，再插上，这次在系统弹窗里点"取消"。
2. App 里应显示"尚未获得 USB 权限"和"申请权限"按钮。
3. 点"申请权限" → 允许 → 应自动开始连接测试。

### D. 插拔 5 次
- 每次拔掉后等几秒再插上，看 App 是否每次都能识别。
- 如果拔插间隔很短，App 会提示"断开后很快又重新连接"，手动插拔时出现属于正常。
- 如果你**没有动线**却出现了这个提示，请一定告诉我：那很可能是供电问题。

### E. 发回结果
1. 点"复制诊断信息"，回到对话里粘贴发送。
2. 内容太长发不出去时，点"导出日志（zip）"保存到"下载"目录，或者点"分享日志"，再想办法发给我。

## 3. 需要你贴回的内容
- 诊断信息全文（最重要）
- 安装时有没有被拦截、系统弹窗里写了什么
- App 有没有闪退或卡住；光驱指示灯、转动有没有异常
- 扩展坞型号（方便的话）

## 4. 如果 App 闪退
重新打开 App，点"复制诊断信息"。崩溃堆栈会在日志里（`E/CRASH`），系统记录的"上次进程退出原因"也会出现在日志开头附近。

## 5. 我会从结果里看什么
- VID/PID、接口（期望 08/06/50）、有没有 UAS 备用设置 → 收窄插入时的自动弹出过滤器
- 链路速度（SuperSpeed 还是降到 USB 2.0）、声明的最大电流
- 平板内核原本给它绑定了什么驱动（usb-storage / uas / 无）
- Get Max LUN 是否正常应答
- 这些决定 N1.2（BOT 传输 + INQUIRY / TEST UNIT READY / REQUEST SENSE / GET CONFIGURATION）的实现细节

## 6. 已知限制
- 现在插任何 USB 存储设备（例如 U 盘）都会弹出本 App；拿到光驱的 VID/PID 后会收窄。
- 这个版本还不会读光盘。
