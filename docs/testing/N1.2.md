# 测试节点 N1.2：光驱通信（BOT 传输 + 基础命令）

- 版本：`0.2.0-N1.2`（versionCode 2），直接覆盖安装 N1.1 即可（签名相同）。
- 这一版第一次真正和光驱"说话"：通过 USB Bulk-Only Transport 发送 SCSI/MMC 命令。
- **只发送白名单里的只读命令**：INQUIRY、TEST UNIT READY、REQUEST SENSE、GET CONFIGURATION、MODE SENSE(10) 2Ah 页、GET EVENT STATUS NOTIFICATION、MECHANISM STATUS、REPORT KEY（只读 RPC 地区状态）、START STOP UNIT（只用于弹出）。写盘类命令和修改地区码的命令根本不在白名单里，发出前就会被拦截。

## 1. 安装
在对话里下载 APK，直接安装（覆盖旧版本）。

## 2. 测试步骤

### A. 不放光盘连接
1. 接上光驱（带供电扩展坞，两个 USB 头都插）。系统弹窗点"确定"。
2. 设备卡片应依次显示"正在连接光驱…" → "光驱：厂商 型号（固件 x.xx）"、"会话：已连接"、"盘片：无盘（托盘已关闭）"。
3. 看"DVD 地区码"一行，记下它显示的内容。

### B. 托盘与盘片
按顺序做，每一步等 2–3 秒再看"盘片"和"事件"：
1. 按光驱上的弹出键打开托盘 → 应显示"无盘（托盘已打开）"（或事件里出现"托盘已打开"）。
2. 放入一张 **CD**（音乐 CD 或数据 CD 都行），推回托盘 → "正在读取盘片…" → "就绪：CD-ROM"（CD-R 会显示 CD-R）。
3. 点 App 里的"弹出光盘" → 托盘弹出，显示"无盘（托盘已打开）"。
4. 换 **DVD** 重复第 2–3 步（显示 DVD-ROM / DVD±R 等）。
5. 换 **BD** 重复（显示 BD-ROM / BD-R / BD-RE）。
6. 放着一张盘时按光驱上的弹出键，看事件里有没有"检测到弹出请求"。

### C. 拔插
1. 在"就绪"状态下直接拔掉光驱 USB → App 应提示"光驱已断开"，卡片消失。
2. 重新插上 → 自动重新连接，盘片状态正确。

### D. 发回结果
点"复制诊断信息"粘贴到对话里。诊断信息里包含：光驱型号、支持的盘片、功能列表、地区码、各命令的**原始响应 hex**（我用来核对解析是否正确）、事件列表、BOT 统计（STALL / 超时 / 复位次数）。

## 3. 需要你告诉我的
- 每种盘片显示的类型对不对（CD / DVD / BD，以及是否可写盘）
- 从推回托盘到"就绪"大概几秒（事件里有"用时"）
- 有没有出现"光驱自行复位——疑似供电不足"或红色错误
- 诊断信息全文

## 4. 我会从结果里看什么
- 光驱的真实机芯型号与固件（INQUIRY）、物理接口（Core 特性）
- 支持的 profile / 特性是否与 BRXL-PTV6U3 规格一致，CD-Text / C2 / CSS / AACS 支持情况（决定 N1.5 和阶段 3 的做法）
- DVD 地区码状态（RPC-II？地区几？剩余修改次数）——这是阶段 3 播放加密 DVD 的前提
- GESN 是否正常、托盘状态是否可靠，BOT 层有没有 STALL/超时/复位
- 这些决定 N1.3（读取盘片信息：容量、TOC、轨道、盘片结构）的实现细节

## 5. 已知限制
- 这一版还不读盘片内容（N1.3 开始读 TOC 和容量）。
- 便携光驱通常不能用命令关闭托盘，需要手动推回去。
- 现在只有插这台 BUFFALO 光驱（0411:036D）才会自动拉起 App；插 U 盘不会再弹出。
